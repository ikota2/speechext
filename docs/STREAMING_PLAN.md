# Speechext — Live Voice-to-Text Streaming

План фичи: запись диалога (свой голос + голоса собеседников из созвона) с инкрементальной транскрипцией в реальном времени.

## Целевой UX-флоу

1. Пользователь открывает Speechext, переключается на таб `Record`.
2. Нажимает Start.
    - При первом запуске macOS просит разрешение на Screen Recording. После согласия — запись стартует.
3. Во время созвона на экране растёт текст, обновляется каждые ~5 секунд.
4. Пользователь нажимает Stop.
5. Диалог: «сохранить аудиофайл? / удалить».
6. (Опционально, отложено) Запускается диаризация на полном wav → текст превращается в размеченный по спикерам.
7. Пользователь нажимает Save → запись попадает в правую панель `Mic → Text` истории.

## Архитектурные решения

| Решение | Выбор | Причина |
|---|---|---|
| Захват аудио | ScreenCaptureKit (нативный macOS) | Захват системного звука + микрофон без BlackHole; macOS 15 поддерживает оба как раздельные потоки |
| Rust binding | `screencapturekit` crate (v1.x) | Активно поддерживается, готовый safe API, не надо писать objc2/Swift |
| Минимальная macOS | 15.0 (Sequoia) | Раздельные потоки mic + system audio через `.with_captures_microphone(true)` |
| Источники аудио | Микрофон + системный звук | Без выбора устройств в UI — ScreenCaptureKit берёт всё нужное сам |
| Микширование | В моно PCM перед отправкой | Whisper всё равно downsamplит до 16kHz mono — миксуем сразу, упрощаем чанкинг |
| Чанк-стратегия | TBD (открыто, см. подзадачу 2) | Решается в момент работы над подзадачей |
| Движок транскрипции | Groq `whisper-large-v3-turbo` | Только для стрима. Файловый режим (таб Open) не трогаем |
| Локальный faster-whisper | Не используется для стрима | На Intel CPU нереалтайм |
| Диаризация | Постфактум после Stop (опц.) | На лету нереально на Intel CPU; pyannote по полному wav |
| Захват свой/чужой голос | Микшируем в один моно-поток | Для MVP. Раздельная маркировка спикеров — задача диаризации (отдельная итерация) |

## Открытые технические решения (решаются в момент работы над подзадачей)

- **Чанк-стратегия для стрима**: скользящее окно (10s/5s) vs VAD по тишине vs гибрид.
- **Контекстный prompt в Groq API**: передавать ли последние N слов предыдущего чанка как context.
- **Sample rate захвата**: 16kHz сразу (под Whisper) или 48kHz (нативный SCK) с ресемплингом перед отправкой.
- **Хранение временного wav во время записи**: ring buffer в памяти vs пишем на диск сразу.

## Подзадачи

Каждая — самодостаточная итерация с понятным «готово». Порядок: 1 → 2 → 3 → 4 для MVP, далее 5 и 6 опционально.

### Подзадача 1. Захват аудио через ScreenCaptureKit

**Входит:**
- Добавить `screencapturekit` крейт в `Cargo.toml`.
- `NSScreenCaptureUsageDescription` в Info.plist через `tauri.conf.json`.
- Tauri-команды `start_recording` и `stop_recording`.
- Захват двух потоков: системный звук (`SCStreamOutputType::Audio`) + микрофон (`SCStreamOutputType::Microphone`).
- Микширование в моно PCM.
- Накопление в wav-файл во временной директории.
- После Stop — wav доступен на диске.

**Не входит:** транскрипция, UI стрима, чанкинг.

**Готово =** нажать Start через тестовую кнопку, поговорить в Zoom-созвоне, нажать Stop, получить рабочий wav в `/tmp` (или аналог), проверить внешним плеером что слышно и тебя, и собеседника.

**Открытые вопросы при работе:**
- Sample rate захвата: 16kHz vs 48kHz с ресемплингом.
- Ring buffer vs прямая запись на диск во время записи.

---

### Подзадача 2. Чанкинг + отправка в Groq

**Входит:**
- Получение потока аудио из подзадачи 1.
- Чанк-логика (стратегия выбирается в начале работы).
- Расширение `transcribe.py` или новый Python-скрипт `transcribe_chunk.py` — принимает один чанк, шлёт в Groq `whisper-large-v3-turbo`.
- Tauri event `transcribe-stream-chunk` с текстом и временной меткой.

**Не входит:** UI стрима (только консольный/лог-вывод), диаризация.

**Готово =** во время записи в консоль/devtools сыпется текст распознанных чанков с timestamps.

**Открытые вопросы при работе:**
- Чанк-стратегия.
- Контекстный prompt.
- Что делать при ошибке API (retry, пропустить чанк, показать в UI).

---

### Подзадача 3. Инкрементальный UI стрима

**Входит:**
- Новый Svelte-компонент (или доработка `Record.svelte`).
- Подписка на events из подзадачи 2.
- Состояние стрима в новом store `stream.svelte.ts` (или расширение `result.svelte.ts`).
- Дописывание текста по мере прихода чанков.
- Корректная обработка перезаписи «хвоста», если стратегия скользящее окно.
- После Stop — текст фиксируется, переход к виду готового результата.

**Не входит:** диаризация, стили (только базовая разметка).

**Готово =** во время записи на экране растёт текст с задержкой ~5 сек, после Stop он зафиксирован и виден целиком.

---

### Подзадача 4. Сохранение результата как `mic-text`

**Входит:**
- Новый тип `mic-text` в существующем save/list/load flow.
- Расширение JSON-схемы: совместимо с `audio-text`, добавляется `type: 'mic-text'`, опционально `audio_path` если пользователь сохранил wav.
- Диалог после Stop: «сохранить аудиофайл? / удалить» — wav остаётся в `~/Speechext/` рядом с JSON или удаляется.
- Проверить что `History.svelte` отображает `mic-text` в своей секции (фильтр уже есть).
- Save-кнопка пишет результат через `saveResult`.

**Не входит:** диаризация в JSON, проигрыватель сохранённого wav.

**Готово =** записал стрим → нажал Save → результат появляется в `Mic → Text` секции истории, клик открывает его в основной области, всё работает как для `audio-text`.

### Подзадача 5. Диаризация постфактум (опционально, отдельная итерация)

**Входит:**
- Установка `pyannote.audio` в `.venv`.
- Новый Python-скрипт `diarize.py` — принимает путь к wav, возвращает JSON со списком сегментов `{start, end, speaker}`.
- Tauri-команда `diarize_result` запускает скрипт на сохранённом wav.
- В UI — кнопка «Определить спикеров» после сохранения, прогресс-индикатор.
- Сопоставление timestamps от диаризации с сегментами от Whisper → размеченный по спикерам текст.
- Расширение JSON: `speakers: ['Speaker_1', 'Speaker_2', ...]`, `segments: [{text, speaker, start, end}, ...]`.

**Не входит:** именование спикеров (только нумерация), realtime-диаризация.

**Готово =** для сохранённой записи нажать «Определить спикеров» → через 2-5 мин текст отображается размеченным по спикерам.

**Открытые вопросы при работе:**
- pyannote или более лёгкая модель (simple-diarizer) — баланс качество/скорость на Intel CPU.
- Где брать pyannote checkpoint (HuggingFace требует токен).
